# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Moni: a personal finance tracker (Spanish UI, Colombian peso). React + TypeScript frontend (`web/`, built with Vite) served as static files by a FastAPI backend backed by SQLite. One process, one port in production; the frontend needs a build step. **All business logic (money, dates, derived fields, upcoming operations, listings) lives in the backend; the frontend only fetches and paints.**

## Running locally

No installed venv/conda env in the repo, set one up ad hoc:

```bash
python3 -m venv .venv && source .venv/bin/activate   # or use conda per user global prefs
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload --port 8080
```

Frontend (Node 22, see `web/.nvmrc`):

```bash
cd web && npm ci
npm run dev      # Vite on http://localhost:5173, proxies /api to http://localhost:8080
npm run build    # writes web/dist
```

For day-to-day work run the backend on 8080 and `npm run dev` in `web/`, then open `http://localhost:5173`. To exercise what production serves, run `npm run build` and open `http://localhost:8080`: FastAPI serves `web/dist` via `StaticFiles` mounted at `/` (`FRONTEND_DIR` in `backend/main.py`). If `web/dist` is missing the backend still starts, logs an error and answers 404 for the frontend (the API keeps working).

**The docroot is `web/dist`, not the repo root**: everything under it is downloadable by anyone who can reach the port, and everything outside it (backend code, the SQLite file, `.git`, `web/src`, `web/package.json`) is not. Don't point `FRONTEND_DIR` anywhere else, and don't put anything in `web/dist` besides the build output. Static assets (fonts, icons, franquicias) live in `web/public/assets/` and are copied into `dist` by Vite with the same URLs.

Via Docker:
```bash
docker compose up --build
```
Serves on port 8080 (mapped to container port 80). SQLite file persists in the `moni-data` named volume at `/app/backend/data`. The Dockerfile is multi-stage: a pinned `node:22.*-slim` stage runs `npm ci` + `npm run build` in `web/`, and the final `python:3.12-slim` image gets only `backend/` plus `web/dist`. No `web/src`, `node_modules`, tests or docs ship in the image.

Backend tests: `pip install -r backend/requirements-dev.txt && python -m pytest backend/tests -q`. They cover card-balance adjustment, the composite actions, input validation, the backup round-trip, the static docroot, the `backend/calculos/` modules, the calculated read endpoints, auth and push. Tests mirror the code: `backend/tests/{api,calculos,push,seguridad}/`; each test gets a throwaway SQLite file via the `client` fixture in `backend/tests/conftest.py`. `calculos/test_parity.py` checks the Python port against `backend/tests/calculos/fixtures/parity.json`, expected values captured from the old TypeScript implementation: don't regenerate it to make a failure go away. `api/test_static.py` reads `web/dist/index.html`, so it **fails (does not skip) until you run `npm run build` in `web/`**. **Add a test when you touch anything that moves money.**

Frontend tests, in `web/`: `npm test` (Vitest + Testing Library + jsdom; the script pins `TZ=America/Bogota` and a setup file asserts it, so timezone bugs surface on any machine), `npm run lint` (ESLint + typescript-eslint + react-hooks), `npm run typecheck` (`tsc -b --noEmit`, strict), `npm run build`. There are no unit tests for money/date math in the frontend any more (it lives in the backend); `web/src/lib/` only tests `api` and `format`. Every feature has Testing Library tests that assert the exact request (method, URL, JSON body, `X-Moni-Request` header) sent to a mocked `fetch` (`web/src/test/mockFetch.ts`, which serves canned responses for the calculated endpoints). jsdom has no layout, so verify visual changes by exercising the app.

**Auth** (`backend/seguridad/`: `password`, `sesiones`, `bloqueo`, `middleware`, `rutas`, `passkeys/`): single owner, password hash in `MONI_PASSWORD_HASH` (`python -m backend.seguridad hash|blocked|unblock <ip>`); unset means every protected route answers 401. Three failures from one IP in an hour block it (`MONI_BLOCK_HOURS`). Login and passkey verification run under `bloqueo.lock_ip(ip)` and re-check the block inside it, otherwise a concurrent burst gets evaluated before the 3rd failure lands. `X-Forwarded-For` is read only from `MONI_TRUSTED_PROXIES` (default loopback); never default it to private ranges, any LAN host could then rotate its IP. Tests get a logged-in `client` and an `anon_client`.

**Mutating requests (`POST`/`PUT`/`DELETE` on `/api/*`) require an `X-Moni-Request` header**, or the backend returns 403 (`require_csrf_header`, `backend/core/csrf.py`). `apiFetch` (`web/src/lib/api/client.ts`) adds it automatically; hand-written `curl` needs `-H 'X-Moni-Request: 1'`. Besides the session cookie (`moni_session`, required on every `/api/*` route except `GET /api/auth/estado`, `POST /api/auth/login` and the passkey login endpoints), this blocks a cross-origin `<form>` POST to a destructive endpoint like `/api/truncate`.

## CI and deploying

`.github/workflows/build-push.yml` has two jobs. `test` runs, in order, `npm ci`, lint, typecheck, `npm test` and `npm run build` in `web/`, then pytest (it needs `web/dist` for `test_static.py`). `build` then builds and pushes to `ghcr.io/<owner>/moni` (tags `latest` + commit SHA) on every push to `main`. Production `docker-compose.yml` (on the home server, via Portainer) points `image:` at that GHCR tag instead of `build: .`; local dev keeps `build: .`. Don't rename the image without updating both, the workflow used to publish as `fondo-familiar` (copy-pasted from the sibling `fondi` repo) before being corrected to `moni`.

## Architecture

**Backend (`backend/`)** — FastAPI app wiring in `main.py`; `api/` (routers, one per resource, plus `crud.py`), `schemas/` (Pydantic models), `core/` (`db.py` SQLite connection/schema, `estado.py`, `montos.py`, `csrf.py`), `calculos/` (pure logic, see below), `seguridad/` (auth) and `push/` (Web Push).
- `core/db.py` defines the schema inline as a `CREATE TABLE IF NOT EXISTS` script, plus a `MIGRATIONS` list of `ALTER TABLE` statements applied on startup (each wrapped in a try/except to no-op if the column already exists). **There is no migration framework** — to change a table shape, add a column to `SCHEMA` *and* append the matching `ALTER TABLE` to `MIGRATIONS` so existing databases pick it up.
- Data tables: `transacciones`, `deudas` (debts, including credit cards via `es_tarjeta`), `inversiones`, `activos`, `recurrentes`. App state that used to live in the browser: `categorias` (custom ones only; system categories are `CATEGORIAS_SISTEMA` in `calculos/listados.py`), `ops_ocultas` (hidden upcoming operations, keyed by `clave`), `ajustes` (key/value, today `moneda_simbolo`). Plus `push_subs`. No SQLAlchemy/ORM — raw SQL via `sqlite3.Row`.
- `register_crud()` (`api/crud.py`) generates POST/PUT/DELETE routes for `deuda`, `inv`, `activo`, `rec` from a `TABLES` dict of (table name, column list). `transacciones` has its own hand-written CRUD instead, because a `gasto` charged to a card (`tarjeta_id` set) must also adjust that card's `deudas.saldo_actual` (see `ajustar_saldo_tarjeta` in `api/transacciones.py`) — every tx create/update/delete has to undo the old balance effect before applying the new one.
- There is **no FK on `transacciones.tarjeta_id`** (SQLite can't add one via `ALTER TABLE`, and rewriting the table on an existing prod db isn't worth it). The invariant is kept in code instead: deleting a `deudas` row nulls out the `tarjeta_id` of its transactions, and `ajustar_saldo_tarjeta` no-ops on a missing card rather than raising. Both matter — raising there used to make orphaned transactions impossible to edit *or* delete, since `delete_tx` goes through the same function.
- Pydantic models carry the domain validation (`Literal` for enums, `Field(gt=0)` for amounts, a regex for dates). Keep it there rather than trusting the frontend — the API is reachable directly.
- **"Composite actions"** (in `api/deudas.py`, `api/inversiones.py` and `api/activos.py`) are POST endpoints beyond plain CRUD that touch two tables in one SQLite transaction — e.g. `/api/deuda/{id}/pago` (loan payment), `/api/inv/{id}/aporte` (investment contribution), `/api/activo/{id}/venta` (asset sale). Each optionally inserts a linked row into `transacciones` (`registrar_tx` on the request body) so the ledger stays consistent with debt/investment/asset state. When adding a new money-moving action, follow this pattern rather than mutating state from the frontend.
  - Flags on the body carry *domain* meaning, and one flag can only mean one thing. `registrar_tx` is bookkeeping ("I already logged this elsewhere"); `capitaliza` (rendimiento) and `avanzar_cuota` (pago) are economics. Overloading `registrar_tx` to also decide where the money went would silently do the wrong thing for anyone who keeps part of the ledger outside Moni.
  - `/api/deuda/{id}/pago` rolls `proxima_cuota` forward a month when `avanzar_cuota` is set, and clears it when the balance reaches zero. Only the monthly cuota sets it — an extraordinary abono or a card payment must not move the due date. Without this the date froze and the debt eventually vanished from "próximas operaciones" for good.
- **`backend/calculos/`** is pure, side-effect-free logic; every function takes `hoy: datetime.date` as a parameter (tests inject it) and only the routers in `api/` resolve it with `fechas.hoy_bogota()`.
  - `fechas.py`: `hoy_bogota`, `normalizar_fecha` (legacy `d/m/yyyy` too), `sumar_meses`, `redondear_js`, month labels.
  - `dinero/`: the money definitions (below).
  - `operaciones/`: derived fields per debt/investment/asset/recurrente (`derivar_*`), rate conversion (`ea_a_mv`), `operaciones_proximas`.
  - `listados.py`: `derivar_tx`, the `/api/tx` listing (filters, sort, date groups), `top_segmentos`, system categories.
- **Read endpoints**: there is no "load everything" endpoint for the UI. `GET /api/bootstrap` carries only session context (`hoy`, `ahora`, `categorias`, `ajustes`, `alertas`, `conteos`, `desactualizado`); `GET /api/meta` carries static option lists for forms (frecuencias, franquicias, tipos, periodos), fetched once. Each tab reads its own calculated view: `/api/dashboard/*`, `/api/tx`, `/api/{deudas,inv,activos,rec}/resumen`, `/api/proximas-operaciones` and `/api/calc/tasa` return ready-to-render data, including domain phrases (`texto_dias`, `grupo`, `frase`) and chart series. `GET /api/{tx,deuda,inv,activo,rec}/{id}` returns one row with its derived fields (what edit forms load). The `*/preview` POSTs compute what a form shows (split capital/intereses, delta, commission) without mutating. `GET /api/all` survives only as the backup export (raw rows plus derived fields, five collections, nothing else; `Backup.tsx` is its one consumer and `POST /api/import` ignores the derived ones). Derived fields are read-only: the frontend must not send them back. When adding a number to the UI, compute it here and expose it; don't compute it in React.
- **Validation errors are Spanish and come from the backend**: `api/errores.py` turns every 422 into `{"detail": [{loc, msg, type}]}` with `msg` in Spanish (`MENSAJES` by Pydantic error type; `ValueError` messages from validators pass through without the `Value error, ` prefix). The frontend shows `detail[].msg` as is; don't translate in React.
- **Time zone**: "today" is `America/Bogota` from the server clock, never the process zone nor `date.today()`, and never the browser. Same traps as ever: no `setMonth` on a day that may not exist (use `fechas.sumar_meses` / `_sumar_un_mes()` in `api/deudas.py`, which anchor the day and clamp it to the month's length), and dates go out normalized as `YYYY-MM-DD` / `YYYY-MM-DDTHH:MM`.
- **Push** (`backend/push/`, routes `/api/push/{key,subscribe,unsubscribe,test}`): a daily asyncio job started in `lifespan` (8:00 America/Bogota) sends today's and tomorrow's upcoming operations to every row in `push_subs`; it assumes a single process (no multiple workers, or it would send duplicates). VAPID keys are generated on first start and persisted as `vapid_private.pem` next to the SQLite file (the data volume); losing it invalidates every subscription. `VAPID_SUBJECT` env sets the VAPID `sub` claim (default `https://moni.nufi.com.co`). Subscription endpoints are checked against an allowlist of browser push hosts (`PUSH_HOSTS`, `endpoint_permitido`): the server POSTs to them, so an arbitrary URL would be SSRF; keep it strict. A 404/410 from the push service deletes the subscription. Push needs HTTPS (service worker + Notification API) and on iOS the PWA installed to the home screen; `web/public/sw.js` and `manifest.webmanifest` are served from the docroot.
- Every route opens its own `sqlite3` connection via `db.get_conn()` and closes it in a `finally` — no connection pooling/dependency injection.

**Frontend (`web/`)** — React 19 + TypeScript (strict, no `any`) built with Vite. Styling is Tailwind CSS 4 + shadcn/ui (Radix primitives in `web/src/components/ui/`, generated by the shadcn CLI; toggles restyled as segmented controls). Entry: `web/src/main.tsx` -> `app/App.tsx` (providers) -> `shell/Shell.tsx`; one stylesheet, `web/src/styles/index.css`. The frontend has **no business logic**: it fetches (`web/src/lib/api.ts`, typed in `web/src/types.ts` to the exact backend shapes) and renders. Only pure UI state stays here: active tab, filters/sort/period selected, drawer, popups, input text, the pending operation key.
  - **Shared form and modal classes** (`form-group`, `form-label`, `form-input`, `form-row-2`, `btn` + `btn-accent|btn-dim|btn-danger|btn-sm`, `icon-btn`, `tipo-toggle`/`tipo-btn`, `modal-*`, `breakdown*`, `progress-*`, `advanced-toggle`, and the `cdd-*`/`cdp-*` hooks of Select/DatePicker) live in `web/src/styles/ui.css` (`@apply` on the tokens). Use them in modal forms; everything else is Tailwind utilities. Some class names (`add-btn`, `skeleton`, `recent-item`, `tab-content`/`active`, `open`, `sel`) stay only as hooks for tests; don't give them styles.
  - **Dashboard conventions:** every dashboard card is a `Panel` (`components/panel.tsx`) that opens with one plain sentence interpreting its numbers, then the chart or list; keep blocks compact. The other tabs open with a `Resumen` instead (same file): big figure, a short fact beside it, and a composition bar of what makes it up (the backend's `top_segmentos` folds the tail into "Otros"). A stale value is the `Desactualizado` icon with a hover/tap tooltip, not a line of text. Neutrals are slate (blue-tinted grays), set in `styles/index.css`. Charts are shadcn `ChartContainer` + Recharts (`components/ui/chart.tsx`); colors come from CSS variables, so they follow light/dark. Four fixed domain colors (`cartera` blue, `inversiones` green, `activos` ochre, `deudas` red) are Tailwind colors; sums are shown as sums (`Total`: a rule and the result). Light and dark follow `prefers-color-scheme`. `src/components/ui/**` relaxes a few type-aware lint rules because it is generated code; the CLI also tends to add a bogus `cn` npm package and import from it: remove it and import `cn` from `@/lib/utils`.
  - **No CDN, ever.** Archivo comes from `@fontsource-variable/archivo` and Recharts from npm, both bundled. This runs on a LAN with no internet.
  - `web/src/shell/` — `providers/` (`DataProvider`: the `estado` object is only the bootstrap payload (`hoy`, `ahora`, `categorias`, `ajustes`, `alertas`, `conteos`, `desactualizado`), loaded from `/api/bootstrap`; `reload(afectadas?)`, banner, `loaded`, and `versiones`, one counter per entity; also runs the one-time localStorage handoff), `ModalProvider` (`openModal`, `closeModal`, `setModalStatus`, pending proximas-operaciones key, focus trap, backdrop click, focus restore; the form renders inside a `ContentBoundary`, so a throwing form closes the modal and shows a banner instead of blanking the app), `CategoriasProvider`, `AuthProvider`), `hooks/` (`useVista(clave, cargar, entidades)` fetches a calculated endpoint and refetches when `clave` or the versions of the entities it depends on change, so a mutation refreshes only the views it affects; `useMeta()` caches `/api/meta` for the session; `usePreview`, `useGuardar`, `useConfirmDelete`, `useMutations` (`crudOp`, `crudOpOrBanner`, `apiAction`; they attach `op_clave` from the modal's pending key), `openers.ts`), `invalidacion.ts` (which entities a mutation to a route invalidates: `tx` affects `transacciones` and `deudas`, `deuda`/`inv`/`activo` also `transacciones`, unknown routes invalidate all), `layout/` (`TabBoundary`, `Shell.tsx` with header nav, shadcn `Sheet` drawer below `lg`, mobile FAB mapped per tab via `FAB_ACTIONS`, stale-value `has-warning` on nav buttons from `estado.alertas`, Escape closes the modal; the Sheet handles its own Escape).
  - `web/src/controls/` — `Select`, `DatePicker`, `MoneyInput`, `AdvancedToggle`, `FormStatus`, `FormFields`, `FormFooter` and `popups.ts` (single active Select/DatePicker popup, outside click, Escape): the custom form controls. Use them instead of native `<select>`/date inputs.
  - `web/src/features/<tab>/` — one folder per tab (`dashboard`, `transacciones`, `deudas`, `inversiones`, `activos`, `recurrentes`, `settings`): `index.tsx` exports the tab component (`{ active }` props, renders `TabContent`) and the openers other features may call; `forms.tsx` holds the modal forms. Import another feature only through its `index.tsx`. All tabs stay mounted, so filters/periods/sort persist across tab switches.
  - `web/src/lib/` — `api/` (`client.ts`: `apiFetch`, `X-Moni-Request` on every non-GET, error parsing of `detail` arrays; one module per area for the endpoint functions), `format/` (money/date/percent formatting at the UI edge, money-input masking, `todayStr`/`isoDate`, franquicia icons), `storage/` (one-time localStorage handoff), `seguridad/` (`auth`, `passkeys`, `push`: session, WebAuthn and service worker clients), `utils.ts` (`cn`, required by shadcn). Don't add domain logic here.
  - `web/src/app/App.tsx` composes the providers; `web/src/types/` holds the API types by area. Tests live in a `tests/` folder next to the code they cover (`shell/tests`, `features/<tab>/tests`) or beside the module in `lib/`.
  - `web/src/test/` — `renderWithProviders`, `mockFetch`, factories, setup.
- **State flow is unidirectional and coarse**: any mutation (`crudOp`/`apiAction`) POSTs/PUTs/DELETEs to the backend, then calls `reload(afectadas)`: it refetches `/api/bootstrap` and bumps the versions of the affected entities so only their views refetch. There is no optimistic update or partial patching, don't try to patch `estado` locally and expect it to stick. On success the order is fixed: `resolvePendingProxOp()`, `closeModal()`, `reload()`.
- `crudOp`/`apiAction` propagate errors so modal forms can show them inline via `setModalStatus('err', ...)`. For mutations fired **outside** a modal (deleting from a card, pausing a recurrente) use `crudOpOrBanner`: it catches, calls `reload()` first and only then `showBanner(message)`. The order matters: a successful reload after the banner used to hide the error. A bare `crudOp` outside a modal leaves a rejected promise nobody handles.
- Each tab renders inside its own `TabBoundary`, so one broken tab shows a "No se pudo dibujar: ..." banner instead of blanking the page. Wrap new tabs the same way.
- **localStorage is no longer app state.** Custom categories, hidden operations and the currency symbol live in SQLite (`categorias`, `ops_ocultas`, `ajustes`). The keys `moni_cats`, `moni_skipped_ops`, `moni_currency_symbol` are only read once by `lib/migracion.ts` and sent to `POST /api/migrar-local` (idempotent, ignores system categories and invalid keys); they're removed only if the call succeeds. Don't write them again. Any remaining localStorage access must be in try/catch.
- **Money definitions live in one place**, `backend/calculos/dinero.py`, and there are *two* of them, don't collapse them:
  - `flujo_cartera()` — what moves available cash. A card `gasto` doesn't (it moves the card's balance), a `transfer` does. Drives the "Cartera" KPI and the savings rate.
  - `flujo_patrimonio()` — what moves net worth. A card `gasto` *does* (it raises the debt); anything in `CATEGORIAS_NEUTRAS_PATRIMONIO` doesn't, because it only shifts money between cartera and a debt/investment/asset. Drives the evolution chart and the 12-month projection.
  - `net_worth()` is the endpoint the evolution chart walks backwards from, subtracting the monthly patrimonio flow. Using the cartera flow there painted every debt payment as if you'd been richer the month before. Revaluations of assets and variable investments leave no transaction, so the historical curve can't see them, only the final point has them.
  - Anything scoped to a month must stay scoped: mixing an all-time total with a current-month one (the savings rate used to) yields three-digit percentages.
  - Rounding mimics the old JS where it mattered (`redondear_js` = `floor(x + 0.5)`, not Python's banker's `round`); `test_parity.py` pins it.
- **A yield counts on one side only, never both** (`/api/inv/{id}/rendimiento`, `capitaliza` flag): if it capitalizes it raises `inversiones.valor_actual` and writes no transaction; if it's paid out it writes an `Intereses` income and leaves the investment's value alone. Doing both — which it used to — inflated net worth by the same peso twice, since `netWorth()` sums the ledger *and* `valor_actual`. Same rule for any new payout-shaped action.
- Interest paid on a debt: prefer the exact `deudas.total_intereses` accumulated by the backend; the estimate is only the fallback for debts with no payments recorded in Moni. The derived `intereses_pagados` is `{valor, exacto}`; the frontend prefixes `~` when `exacto` is false.
- React escapes text, so there is no `escHtml`. Never use `dangerouslySetInnerHTML` or `innerHTML`.
- The dashboard's "Próximas operaciones" widget (`features/dashboard/components/ProximasOperaciones.tsx`) just renders `GET /api/proximas-operaciones`: the backend recomputes upcoming deuda cuotas / inversion yields / recurrente charges (`operaciones_proximas`) and filters out the keys in `ops_ocultas` (`${tipo}:${fuente_id}:${fecha}`). Clicking the check opens the matching form but only stakes a *pending* key in `ModalProvider` (`setPendingProxOp`); `useMutations` sends it as `op_clave` on the next successful tx create / `pago` / `rendimiento`, and the backend hides the operation in the same transaction as the write. `closeModal()` clears the pending key on cancel/escape/backdrop-click. Don't hide eagerly on click, that regressed to canceling the popup silently dropping the operation without registering anything. The X button calls `POST /api/ops-ocultas` directly. The backend prunes stale keys from `ops_ocultas` (on startup and at the end of the GET), so a failed fetch can't wipe them.
- Escape closes the open Select/DatePicker popup first (capture-phase listener in `controls/popups.ts`); only a second Escape closes the modal.

## Conventions specific to this repo


- **Don't block pinch-zoom.** It has been re-broken twice by two different mechanisms: `user-scalable=no`/`maximum-scale` in the viewport meta plus `preventDefault` on gesture/touch events, and then `touch-action: pan-x pan-y` on `*` (that list without `pinch-zoom` disables the gesture just as hard). Fails WCAG 1.4.4, and the amounts are set in small mono type on mobile.
- **Anything clickable must be reachable by keyboard.** Use a `<button>`/`<a>`; a `<tr onClick>` or `<th onClick>` is not focusable on its own and needs `tabIndex={0}`, a `role`, and an Enter/Space handler. Both regressed here before; the transaction rows and the sortable headers are the worked examples.
- Domain vocabulary is Spanish throughout backend and frontend (`deuda`=debt, `inversion`=investment, `activo`=asset, `recurrente`=recurring item, `tarjeta`=card, `monto`=amount, `saldo`=balance, `cuota`=installment). Keep new identifiers consistent with this rather than mixing in English domain terms — this deviates from the user's general "code in English" preference, but matches the rest of this codebase.
- Money is stored/passed as plain numbers (COP, no cents); formatting/parsing to `es-CO` locale strings happens only at the UI edges (`web/src/lib/format/`). The columns are SQLite `REAL`, so every computed balance goes through `pesos()` (`backend/core/montos.py`) before being written — the pro-rata in a partial withdrawal produces fractions every time, and a balance "at zero" left at 1.16e-10 keeps a paid-off debt counting as active forever. "Is there anything left to pay" is `tiene_saldo()` (`saldo_actual >= SALDO_MINIMO`, exposed as the derived `activa`), not `> 0`: rows written before the rounding still carry the residue.
- Dates are normalized to `YYYY-MM-DD` (or `YYYY-MM-DDTHH:MM`) by the backend (`normalizar_fecha`); the frontend's `normDate()` (`web/src/lib/format/`) is only for the strings it builds itself.
- **Never `new Date('YYYY-MM-DD')` in the frontend.** That parses as midnight *UTC*, which in GMT-5 is 19:00 the day before. Build from components, as `mediodia` in `web/src/lib/format/` does; going out, `toISOString()` re-shifts a local date, use `todayStr`/`isoDate`. ESLint bans `new Date('literal')`, date-string concatenation and `.toISOString()`. Anything that depends on "today" comes from the backend (`hoy`), not the browser.
- **Never `setMonth(+n)` on a day-of-month that may not exist.** "31 de febrero" silently rolls into March and the series stays shifted from then on. Anchor the day and clamp it to the month's length — see `fechas.sumar_meses()` (`backend/calculos/fechas.py`) and `_sumar_un_mes()` (`api/deudas.py`).
