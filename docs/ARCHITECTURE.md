# Architecture

Moni is a single FastAPI process that serves a REST API over SQLite and, from the same port, the built React frontend as static files. The boundary that matters most: all business logic (money, dates, derived fields, listings, upcoming operations, user-facing phrases) lives in the backend; the frontend only fetches ready-to-render data and paints it.

## System context

One owner uses it from a phone (installed PWA) or a desktop browser, on a home server or behind an HTTPS reverse proxy. The only outbound traffic is Web Push: the backend POSTs to the browsers' push services (FCM, Apple, Mozilla, Windows), and the endpoint of every subscription is checked against an allowlist because the server calls it. If a push service is down or a subscription expired, that notification is lost and an expired subscription is deleted; the app itself keeps working. There is no bank sync, no external API and no CDN: the font and charts are bundled, so it runs on a LAN without internet.

## Layer map and dependency rule

| Layer | Lives in | May depend on |
|---|---|---|
| Routers | `backend/api/`, `backend/push/rutas.py`, `backend/seguridad/rutas.py` | `schemas`, `core`, `calculos`, `seguridad` |
| Schemas | `backend/schemas/` (request bodies, `respuestas/` response models) | `calculos` (validators) |
| Core | `backend/core/` (SQLite, row helpers, affected entities, backup import) | `calculos`, `schemas` |
| Calculations | `backend/calculos/{base,catalogo,dinero,operaciones}/` | each other, never `api`, `core` or `schemas` |
| Security | `backend/seguridad/` | `core`, `calculos`, `schemas/respuestas` |
| Push | `backend/push/` | `core`, `calculos`, `seguridad`, `schemas/respuestas` |
| Frontend | `web/src/` | the HTTP API only, typed by `web/src/types/api.gen.ts` |

`calculos/` is pure: no I/O, and every function takes `hoy` as a parameter, so tests inject the date and only routers resolve it with `hoy_bogota()`. Financial math never lives in JSX.

## Data and storage

One SQLite file, `backend/data/moni.db`, in WAL mode, with raw SQL through `sqlite3.Row` (no ORM).

- **Data tables:** `transacciones`, `deudas` (loans and credit cards, told apart by `es_tarjeta`), `inversiones`, `activos`, `recurrentes`.
- **App state:** `categorias` (custom ones; system ones are constants), `ops_ocultas` (hidden upcoming operations, keyed by `tipo:fuente_id:fecha`), `ajustes` (key/value, today the currency symbol).
- **Security and push:** `sesiones`, `intentos_fallidos`, `ips_bloqueadas`, `passkeys`, `challenges`, `push_subs`. `vapid_private.pem` sits next to the database file.
- **Migrations:** `SCHEMA` is a `CREATE TABLE IF NOT EXISTS` script; changes to existing tables are `ALTER TABLE` statements in `MIGRATIONS`, and `PRAGMA user_version` stores how many have been applied, so each runs once.
- **Money** is stored as plain COP numbers in `REAL` columns, rounded half-up to whole pesos (`pesos()`) before every write.
- **Invariants the code relies on:** there is no foreign key on `transacciones.tarjeta_id`, so deleting a debt nulls it in its transactions and card balance adjustments no-op on a missing card. A card expense must adjust `deudas.saldo_actual`, undoing the old effect before applying the new one. A yield counts on one side only: capitalized into `valor_actual` or paid out as income, never both.
- **Concurrency:** composite actions (payment, contribution, withdrawal, sale, transaction writes) start with `BEGIN IMMEDIATE` (`core/sql.iniciar_escritura`), so two requests on the same row serialize instead of reading the same balance.

## Request flow

- **Reads:** `GET /api/bootstrap` carries session context (today, categories, settings, alerts); `GET /api/meta` carries every static option list; each tab reads its own calculated endpoint (`/api/dashboard/*`, `/api/tx`, `/api/*/resumen`, `/api/proximas-operaciones`). Responses include domain phrases and chart series, so the frontend computes nothing.
- **Writes:** `POST`/`PUT`/`DELETE` need the `X-Moni-Request` header and a session. The response carries `X-Moni-Afectadas` with the entities whose views must refetch, and the frontend refetches only those. There is no optimistic update.
- **Auth:** a middleware requires the session cookie on every `/api/*` route except the login and status ones. Import, wipe and passkey registration additionally require the password again (`seguridad/step_up.py`). `seguridad/limite_body.py` rejects request bodies over 1 MB (10 MB for `/api/import`) with 413.
- **Contract:** every route declares a `response_model`; `python -m backend.openapi` prints the schema and `npm run gen:types` in `web/` turns it into `web/src/types/api.gen.ts`. CI fails if the committed file is stale.

## Glossary

Code and UI use Spanish domain terms; this doc uses the English ones.

| In code | In English | Meaning |
|---|---|---|
| `transaccion` / `tx` | transaction | A ledger row: `ingreso`, `gasto` or `transfer` |
| `deuda` | debt | A loan or, with `es_tarjeta`, a credit card |
| `inversion` | investment | Fixed-rate (CDT style) or variable (funds, crypto) |
| `activo` | asset | Real estate, vehicles and other holdings |
| `recurrente` | recurring item | A repeating income or expense |
| `cuota` | installment | The monthly payment of a loan |
| `abono` | extra payment | A payment beyond the cuota; does not move the due date |
| `saldo` | balance | What is left to pay on a debt |
| `tasa_ea` / MV | effective annual / monthly rate | The stored rate is EA; MV is derived |
| `cartera` | cash | Available money, as opposed to net worth |
| `proximas operaciones` | upcoming operations | Projected installments, yields and recurring charges |

## Decision log

| Decision | Why | Trade-off |
|---|---|---|
| All logic in the backend | The money and date math used to live in the frontend in TypeScript; it was ported to Python and `test_parity.py` pins the port against values captured from the original | Every number needs an endpoint field; the frontend cannot compute even small derivations |
| Two money definitions, `flujo_cartera` and `flujo_patrimonio` | A card expense changes net worth but not available cash; using the cash flow for the net worth chart painted every debt payment as richer-before | Two similar functions that must not be merged |
| "Today" is `America/Bogota` from the server clock | A date parsed as UTC midnight is 19:00 of the previous day in GMT-5, and the browser or process zone can differ from the owner's | Needs the server clock to be right |
| SQLite, one process | One owner and personal-finance volumes; one file to back up | The daily push job assumes a single process, so no multiple workers |
| No migration framework | A short list of `ALTER TABLE` statements tracked by `PRAGMA user_version` is enough for one database | Rewriting a table on a production database is not supported, which is why `transacciones.tarjeta_id` has no foreign key |
| Composite actions in the backend, in one transaction | A payment, contribution or sale touches two tables and must stay consistent with the ledger | Each new money-moving action needs its own endpoint |
| Pending key for upcoming operations | Hiding on click lost the operation when the user cancelled the form | The key travels as `op_clave` and is consumed in the same transaction as the write |
| `X-Moni-Request` header on mutations | Blocks a cross-origin form POST to a destructive endpoint | Hand-written `curl` must send it |
| `MONI_TRUSTED_PROXIES` defaults to loopback | Trusting private ranges lets any LAN host rotate its IP and dodge the lockout | Behind a proxy it must be set, or every client shares one IP |
| Types generated from OpenAPI | The frontend types equal the backend response models, and CI fails when the committed file is stale | `npm run gen:types` after any schema change |
| Bundled font and charts, no CDN | It runs on a LAN with no internet | Larger bundle |
